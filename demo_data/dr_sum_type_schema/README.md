# Dr.Sum 物理カラム ダミースキーマ・実データ

Dr.Sumがサポートする8種類のデータ型(REAL, NUMERIC, VARCHAR, INTERVAL, DATE, TIME, TIMESTAMP, OBJECT)を、特定の業務テーマに偏らせず網羅するために作成したダミースキーマと、各テーブル5,000行の実データです。

## ファイル一覧

- `data/テーブル定義.md`: テーブル・カラムの定義書(型・精度・NULL可否・説明、型カバレッジ確認表)
- `data/テーブル定義.sql`: 対応するCREATE TABLE文
- `data/T_配送案件.csv` / `.sql`: 配送案件データ(5,000行)+ INSERT文
- `data/T_設備保守履歴.csv` / `.sql`: 設備保守履歴データ(5,000行)+ INSERT文
- `data/T_契約情報.csv` / `.sql`: 契約情報データ(5,000行)+ INSERT文
- `data/T_問い合わせ対応記録.csv` / `.sql`: 問い合わせ対応記録データ(5,000行)+ INSERT文
- `data/T_勤怠記録.csv` / `.sql`: 勤怠記録データ(5,000行)+ INSERT文

CSVはUTF-8(BOM付き)で、Excelでそのままダブルクリックして開けます。SQLはINSERT文のみ(1000行ごとにVALUESを区切っています)で、テーブル自体の作成は`テーブル定義.sql`を先に実行してください。

## データの作り方(技術メモ)

VARCHARのコード列・DATE列・NUMERIC/REAL相当の数値列は[[dummygen_jp_gui]]のエンジン(`dummy_data_gen` CLI)で生成しました(各テーブルごとのschema.yamlでseedを固定: 20261006〜20261010、連番+コードプレフィックスで値の一意性を保証)。

一方、TIME・TIMESTAMP・INTERVAL・OBJECTの4型は`dummy_data_gen`にネイティブ対応する列タイプが無いため(時刻・日時・期間を正しい範囲(0-23時/0-59分等)で生成する専用ロジックが無く、`pattern`列タイプでは桁ごとの数値範囲を制約できないため)、生成したCSVに対してPythonの後処理スクリプトで追加しました(`random.Random`に固定シードを設定、再現可能)。

- TIME列: `HH:MM:SS`(業務時間帯に合わせた範囲でランダム生成。例: 点検開始時刻は8〜17時)
- TIMESTAMP列: `YYYY-MM-DD HH:MM:SS`(関連するDATE列から数日前など、業務的に自然な範囲でオフセット)
- INTERVAL列: `D HH:MM:SS`(日 時:分:秒。日数のみの期間は`D 00:00:00`)。Dr.Sumの正式なINTERVAL表示形式は未確認のため、実際にDr.Sumへ取り込む際はこの表記で問題ないか確認してください。
- OBJECT列: ダミーのファイル名文字列(例: `点検報告書_MN-000001.pdf`)。実バイナリは含みません。一定割合(添付ファイル列は30〜60%程度)をNULL(添付なしの意味)にしています。

NULL可の列には、業務的にありそうな割合(5〜30%程度)でNULLを混ぜています。各コード列(配送案件コード等)は5,000行すべてでユニークであることを確認済みです。

## Dr.Sumへの取り込みに関する注意

- `テーブル定義.sql`のCREATE TABLE文は一般的なSQL構文を想定した記載であり、Dr.Sumの正式なDDL方言(型名表記・最大桁数・PRIMARY KEY対応状況・OBJECT型の制約)は未確認です。実行前にDr.Sum公式のSQLリファレンスで確認してください。
- テーブル名(`T_配送案件`等)・カラム名は、既存デモデータ(`T_売上明細`、`T_顧客M`、`T_商品M`、`T_在庫`、`V_売上_月次集計`)と重複しないことを確認済みです。
- 本スキーマには業務的な自然キー・外部キー関係は設けていません(型の網羅が目的のため、テーブル間の結合は意図していません)。
