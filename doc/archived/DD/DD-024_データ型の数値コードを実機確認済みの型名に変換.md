# DD-024: データ型の数値コードを実機確認済みの型名に変換

| 作成日 | 更新日 | ステータス | 補足 |
|--------|--------|-----------|------|
| 2026-10-06 | 2026-10-06 | 完了 | 0/3/7の3コードを型名変換。実機確認済み。D-004/V001仕様書更新済み |

> アプローチ: 標準（既存の`formatDataType`に実機確認済みの対応表を追加するだけの小規模な変更。guides.md §1）
> リスク: なし（認可・認証／DBスキーマ・マイグレーション／外部I/F／機密情報・決済のいずれにも該当しない）

## 目的

[DD-021](../archived/DD/DD-021_ビューア表示の改善3件.md)で「対応表が未確認のため変換しない」としていたデータ型の数値コードのうち、ユーザーが実機のDr.Sumから取得したデータで確認できた3種類（`0`=VARCHAR、`3`=DATE、`7`=NUMERIC）を実際の型名に変換して表示する。

## 背景・課題

DD-021時点では、[D-004](../decisions.md)・[DD-002-2](../archived/DD/DD-002-2_Dr.Sum実環境対応.md)の「`column_type`の数値コード→型名の対応表は未確認」という決定を踏襲し、数値コードに「(内部コード)」という注記を付けるだけに留めていた。

その後ユーザーが、`dr_sum_metadata.py --host ... --out real_columns.json`で実機のDr.Sum（ホスト`localhost`、DB`Test`）から3テーブル・25カラムのメタデータを取得し、提供してくれた。カラム名から推測される型と`data_type`の値を突き合わせたところ、以下の通り一貫した対応が確認できた。

| `data_type` | 出現したカラム（抜粋） | 推測される型 | 出現回数 |
|---|---|---|---|
| `0` | customer_name, prefecture, product_category, payment_method, gender, membership_rank, store_name, employee_name, department | VARCHAR（文字列） | 10/25 |
| `3` | order_date, birth_date, registration_date, last_purchase_date, record_date | DATE（日付） | 5/25 |
| `7` | order_id, quantity, unit_price, sales_amount, custmer_id, purchase_count, total_purchase_amount, record_id, sales_target, sales_actual | NUMERIC（数値。IDも金額も同一コードのため、整数/小数を区別しない汎用の数値型と判断） | 10/25 |

25件全てがこの3パターンに収まり、矛盾する例は無かった。これはDD-002-2の調査メモにあった推測（VARCHAR系=0、DATE系=3、REAL/NUMERIC系=7）と一致する。

なお、TIME/TIMESTAMP/INTERVAL/OBJECTの4型については、ユーザーが実機への追加データ投入（ダミーCSVのインポート）を試みたが、Dr.Sumのインポートウィザード側で`string code convert is failed`エラーが発生し確認できなかった（Shift-JIS変換後も再現、原因未特定）。これらの型は本DDの対象外とし、引き続き数値のまま「内部コードです」の注記表示とする。

## 決定事項

- `formatDataType`に、実機確認済みの3コード（`0`→VARCHAR、`3`→DATE、`7`→NUMERIC）のみを対応表として実装する
- 対応表に無い数値（TIME/TIMESTAMP/INTERVAL/OBJECT等、未確認の値）は、DD-021と同じく「内部コードです」という注記付きで数値のまま表示する（誤った型名を出すリスクを避けるため、確認できた値のみを変換する方針を維持）
- [doc/decisions.md](../decisions.md) D-004を更新し、「未確認」から「一部確認済み（0/3/7のみ）」へ状態を変更する

## エビデンス

組み込みブラウザ（`web-viewer-demo`設定）がバックグラウンド表示のためスクリーンショットが撮影できなかった（`preview pane is hidden`）ので、`javascript_tool`でのDOM確認で代替した（guides.md §9「Playwright MCP が利用できない場合」に準じる）。

```
openTableDefPanel('T_在庫', 'SOKO_CD'); // 任意のテーブル定義パネルを開いた状態で
formatDataType('0')  → "VARCHAR"
formatDataType('3')  → "DATE"
formatDataType('7')  → "NUMERIC"
formatDataType('12') → "12<span class=\"type-code-note\" ...>(内部コード)</span>"  (回帰: 未確認コードは従来通り)
formatDataType('VARCHAR') → "VARCHAR"  (回帰: 元から型名文字列の場合はそのまま)
```
実際のテーブル定義パネルのtbodyにも上記4コードの行を注入し、`<td>`内のレンダリング結果（VARCHAR/DATE/NUMERIC/12+内部コード注記）がそのまま表示されることをDOM上で確認した。コンソールエラーなし。
