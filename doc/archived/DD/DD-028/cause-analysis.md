# DD-028 原因分析

## Bug#001: `達成率ダッシュボード`のほぼ全列に`true`という無関係なエイリアスが記録される

**ファイル**: `board_parser.py` `auto_parse_xml()`内`walk()`/`find_label_on_element()`(DD-027での`NON_ALIAS_CONTEXT_TAGS`/`_in_non_alias_context()`リネーム後の行番号は要再確認)

**現象**:

`lineage.db`で`達成率ダッシュボード`ボードを調べると、`会社名`/`価格`/`受注日`/`品名`/`地域`/`売上額`/`数量`/`氏名`/`支店`等、ほぼ全列に`display_name='true'`のレコードが存在する(DD-027修正前の`lineage.db`で14件確認)。

**原因（DD-027の横展開調査、Explore agentによる実機確認。2026-10-08）**:

実機`C:\MotionBoard64`の`達成率ダッシュボード.fs-file`内`dsDef/月次売上明細`のXMLを直接確認した結果、以下の構造が存在する(推定復元):

```xml
<Item id="9" fid="9" title="価格" aliasTitle="" type="NUMBER" disp="true" orderNum="9" ... />
```

これはMotionBoardのデータソース定義(dsDef)内の1フィールド定義要素で、`disp`属性は「この項目を一覧に表示するかどうか」のON/OFFフラグ(真偽値)である。`title`(物理カラム名)に対する正規の表示名上書きは`aliasTitle`だが、これが空文字(未設定)のため、`walk()`の汎用ヒューリスティックが同一要素内の他の属性からラベル候補を探しにいく。

このとき`LABEL_KEY_HINTS = ("label", "disp", "name", "alias", "title", "caption", "表示", "名称")`に**`"disp"`という文字列そのもの**が含まれているため、属性キー`disp`(完全一致)がラベルらしい属性として最優先で選ばれてしまい、本来は無関係な真偽値である属性値`"true"`がそのままカラムのエイリアスとして記録される。

`達成率ダッシュボード`では`価格`以外のほぼ全列で同じ`disp="true"`を持つ`Item`要素が存在するため、同ボードのdsDef全体で網羅的に`true`誤抽出が発生している。

### DD-023/DD-027との関係

DD-023(`SearchCondition`配下の`dispTitle`誤抽出)・DD-027(`ItemOrderChange`配下の軸属性誤抽出)と同じ欠陥クラス(物理カラム名と一致した属性と、ラベル候補として拾う属性の間に意味的関連性の検証が無い)だが、**発生箇所とガードの当て方が異なる**:

- DD-023/DD-027のガード(`NON_ALIAS_CONTEXT_TAGS`/`_in_non_alias_context()`)は「祖先要素のタグ名」で配下サブツリーごと除外する方式。`SearchCondition`や`ItemOrderChange`のような「複数の無関係なフィールド参照を同居させるタグ」には有効
- 本バグは**タグの問題ではなく、`Item`要素自身の属性キー名(`disp`)が`LABEL_KEY_HINTS`に(ほぼ)完全一致してしまう**という、属性名ヒューリスティック自体の弱点。祖先タグ配下除外では塞げない

そのため、DD-027のスコープには含めず、本DDとして別途対応する。

**再現手順(フィクスチャでの再現。Phase 0で実施予定)**:
1. `<DataSource type="drsum">`を持たない(汎用ヒューリスティック経路を通る)ボード本体XML内に、`<Item title="<物理カラム名>" aliasTitle="" disp="true">`相当の要素を含むフィクスチャを作成
2. `auto_parse_xml`で解析し、`display_name='true'`のレコードが生成されることを確認(修正前)

**実機での再現(ブロック中。Phase 0で状況確認)**:
`達成率ダッシュボード.fs-file`の現在のスナップショットは`board_parser.py`で0件(パースエラー)になることをDD-027検証時(2026-10-08)に確認済み([DD-027/verification.md](../DD-027/verification.md)参照)。これは本バグの修正前・修正後いずれでも同じ結果であり、本バグ自体とは無関係な別事象(スナップショットが解析不能な状態になっている)と考えられる。実機の生データでの再現確認は、別途取得し直した解析可能なスナップショットが必要。
