# DD-032 原因分析

## Bug#001: ボード別ドリルダウンで「物理名のまま使用」を本物のエイリアスと区別できない

**ファイル**: `web_viewer.py` L1362-1370 `renderDrilldown()`

**現象**: ボード別ドリルダウンの「種別」列は、`usage_type==='calc'`なら「計算式」、それ以外は
無条件に「エイリアス」バッジを表示する。しかしMotionBoard上で表示名(aliasTitle)を一切設定せず
物理カラム名をそのまま使っているケースでも`usage_type`は`"alias"`のままのため、「本当にエイリアスが
命名された」行と「物理名をそのまま使っているだけ」の行が画面上で区別できない。

**原因**: これは[DD-022](../../archived/DD/DD-022_使用ボード欄の物理名そのまま表示をエイリアスと誤認させない対応.md)で
メイン一覧の「使用ボード」欄に対して修正済みの欠陥と同根。DD-022は`renderBoardGroup()`
(L949-961)に`physicalName`引数を追加し、`normalizeText(表示名) === normalizeText(物理名)`なら
`.unaliased`クラス+「(物理名のまま)」付記で区別する対応を行ったが、**この判定はボード別
ドリルダウンの`renderDrilldown()`には適用されていない**。両者は`/api/board_details`
(`fetch_board_details()`)という同じ生データを別々の画面に描画しているが、DD-022当時は
「使用ボード」欄のみが修正対象だったため、ドリルダウン側は見落とされたまま残っていた。

**再現手順**:
1. `python web_viewer.py --db lineage.db` でビューアを起動
2. ボード別ドリルダウンで`09_結合データソース`を選択する
3. `jisseki_nenji.支店`等、MotionBoard上でエイリアス未設定の行の「種別」列が、
   実際にエイリアス設定されている行(`branch_annual.支店`→`store_name`等)と同じ
   「エイリアス」バッジで表示され、区別できないことを確認する

## Bug#002: 「アイテムID」列の意味が画面上で説明されていない

**ファイル**: `web_viewer.py` L361-380（ボード別ドリルダウンの`<table id="drilldown-table">`見出し）

**現象**: 「種別」「アイテムID」列にホバー説明(`title`属性)が無く、特に「アイテムID」が
何を指す値なのか画面から読み取れない。

**原因**: `アイテムID`は抽出経路によって意味が異なる内部識別子であり、ユーザー向けの説明が
そもそも用意されていなかった:
- `<DataSource type="drsum">`専用パーサー(`_parse_drsum_datasource`、`board_parser.py` L287)
  ではデータソース定義内`<Item id="...">`のid属性(そのデータソースのフィールド定義一覧に
  おける内部ID)
- 汎用ヒューリスティック(`find_ancestor_id`、`board_parser.py` L409-414)では、祖先要素から
  `id`/`no`/`seq`/`key`/`index`/`番号`/`コード`のいずれかにマッチする属性値を機械的に拾った
  もので、構造によってどの要素のIDを指すかが変わる

「種別」列も、エイリアス/計算式のバッジの意味（表示名が明示的に設定されているか／カスタム項目・
事後計算項目の計算式内で参照されているだけか）がホバーで説明されていない。

**次のアクション**: 両バグとも画面表示にのみ関わり、原因・対応方針は本分析の時点で確定している
ため、DD本体の「修正方針」に従いPhase 1へ進む（ユーザーには既に口頭で方針を説明し「両方直して
ください」の合意を得ている）。
