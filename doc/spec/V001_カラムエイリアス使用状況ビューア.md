# 画面仕様書: カラムエイリアス使用状況ビューア

---

## 概要・業務目的

カラムエイリアス使用状況ビューアは、Dr.Sumの物理カラムとMotionBoard上の表示名（エイリアス）の対応関係を一覧確認するために、本ツールの利用者（データ基盤担当者・MotionBoard運用者）が使用する画面。具体的には、`lineage.db`（Dr.Sum側カラム一覧とMotionBoard側エイリアスを突き合わせた結果）を読み込み、表記ゆれ候補・多対1候補・物理名直接使用・未使用カラムなどを一覧表示し、意図的な別名はホワイトリスト登録して除外できる。

本画面は単一のHTML（`INDEX_HTML`）で、以下の3つの提供形態を兼ねる:

| 提供形態 | 起動方法 | 用途 |
|---------|---------|------|
| ローカルサーバー版 | `python web_viewer.py` | 自分のPCで`lineage.db`を確認 |
| 静的配布版 | `python export_static.py`で書き出した単一HTML | Pythonなしで他者に配布・閲覧してもらう |
| ブラウザ内評価モード | ローカルサーバー版の「実データをアップロードして見る」ボタン | サーバーを立てず`lineage.db`をブラウザ内（sql.js）だけで解析して見る |

業務上の位置づけ: `dr_sum_metadata.py`→`board_parser.py`→`match_aliases.py`で生成された`lineage.db`を人が目視確認する、パイプラインの最終段階（利用ガイド参照: [`doc/guide/user-guide.md`](../guide/user-guide.md)）。

## ビジネスルール

| 状態 | 操作 | 結果 |
|------|------|------|
| `lineage.db`が存在する（ローカルサーバー版） | 画面を開く | 一覧・統計カード・ボード別ドリルダウンが表示される |
| `lineage.db`が未生成（`--connect`起動直後） | 画面を開く | 各APIが404エラーを返し、「Dr.Sumに接続」から作成するよう案内される（`_require_db`、DD-007） |
| カラムの表示名が複数種類ある（1対多） | - | 「表記ゆれ候補」として一覧行がオレンジ表示＋赤枠バッジになる |
| 異なる物理カラムに同じ表示名がある | - | 「多対1マッピング候補」テーブルに別行で表示される（本体一覧とは別枠） |
| 表示名が1件もなく物理名がそのまま使われている | - | 「物理名そのまま」バッジが付く。ホワイトリスト対象外（事実の指摘のため） |
| MotionBoardのどのボードからも参照されていない | - | 「未使用（孤立項目）」として表示。ホワイトリスト対象外 |
| 表記ゆれ候補・多対1候補・類似度候補の行 | 「ホワイトリストに追加」→ 理由（任意）を入力して登録 | 当該カラムが以後の表記ゆれ集計から除外される（`naming_whitelist.json`に追記） |
| 静的配布版／アップロードモードで閲覧 | ホワイトリスト追加・削除を試みる | ボタン自体が表示されない（保存先サーバーがないため。`STATIC_EXPORT`/`UPLOADED_MODE`判定） |
| `--connect`未指定でローカルサーバー起動 | 「Dr.Sumに接続」フォームから取得を実行 | 403エラー（`connect_enabled`が`False`のため無効） |

## 権限・認可

### ロール × 操作 マトリクス

本画面は認証機構を持たない単一ロール運用のため、ロール区分はない。提供形態によって操作可否が変わる。

| 操作 | ローカルサーバー版（通常起動） | ローカルサーバー版（`--connect`起動） | 静的配布版／アップロードモード |
|------|:---:|:---:|:---:|
| 画面表示・検索・絞り込み・ドリルダウン | ✅ | ✅ | ✅ |
| ホワイトリストへの追加・削除 | ✅ | ✅ | ❌（表示のみ、ボタン非表示） |
| Dr.Sumへの接続・`lineage.db`再生成 | ❌（フォーム自体はあるが403） | ✅ | ❌ |

### 認可境界（どの層で守っているか）

| 層 | 制御内容 |
|----|--------|
| ネットワーク到達性 | `web_viewer.py`は`ThreadingHTTPServer`をlocalhostのみで待受（外部公開しない設計。AGENTS.md） |
| API（`/api/connect`） | `Handler._handle_connect`が`self.server.connect_enabled`（`--connect`フラグ由来）を確認し、無効時は403を返す |
| フロントエンド表示 | `STATIC_EXPORT`/`UPLOADED_MODE`フラグでホワイトリスト操作ボタン・接続フォームの表示有無を切り替える（表示制御のみで、バックエンド側ガードの代わりにはしていない） |
| 認証情報の扱い | Dr.Sumパスワードはクエリ文字列・コマンドライン引数に乗せず、`/api/connect`のPOSTボディ経由で受け取り、`main.py`実行時は環境変数`DR_SUM_PASSWORD`に渡す（`_handle_connect`） |

## 画面UI仕様

### 主要UI要素

- **更新用コマンド入力補助（`update-hint`）**: フォーム（バックアップフォルダ・ホスト名・DB名・ユーザー名・JDBCドライバーパス）に入力すると、`lineage.db`再生成用のコマンドが生成され、コピーボタンで取得できる（DD-008/DD-009）
- **モード切替（`mode-toggle`）**: 「このデータを見る」「実データをアップロードして見る」「Dr.Sumに接続」の3ボタンでパネル表示を切り替える
- **アップロードパネル（`upload-panel`）**: `lineage.db`ファイルと`naming_whitelist.json`（任意）をブラウザ内（sql.js）で読み込み、サーバーなしで同じ画面を描画する（DD-006）
- **接続パネル（`connect-panel`）**: ホスト名・DB名・ユーザー名・パスワード・JDBCドライバーパス・MotionBoardバックアップフォルダ・ホワイトリストファイル（任意）・類似度閾値（任意）を入力し「取得」を実行すると`/api/connect`経由で`main.py`を実行する（DD-007）
- **統計カード（`cards`）**: 総カラム数・表記ゆれ候補・使用箇所(延べ)・カスタム項目/計算式で使用・物理名そのまま・未使用カラム・多対1候補・類似度候補の8種。「表記ゆれ候補」「物理名そのまま」「未使用カラム」の3枚はクリックで一覧を絞り込める（トグル式）
- **検索ボックス（`search`）**: 物理カラム名・テーブル名・表示名・ボード名の部分一致でメイン一覧を絞り込む
- **メイン一覧テーブル**: テーブル/ビュー名・物理カラム名・表示名（複数バッジ表示、表記ゆれは警告色）・使用状況（計算式使用・未使用）を表示。列見出しの←/→ボタンで列の表示順を入れ替え可能、列見出しクリックで値の昇順/降順/初期順ソートが可能（DD-009 Phase 3・Phase 4）
- **多対1マッピング候補テーブル**: 異なる物理カラムが同一表示名を持つ組を一覧表示
- **類似度候補テーブル**: 表示名同士の類似度（`--similarity-threshold`、既定0.8）に基づく表記ゆれ候補ペアを一覧表示
- **ホワイトリスト一覧テーブル**: 登録済みの除外設定（テーブル名・物理カラム名・理由）を表示。通常モードのみ「削除」ボタンあり
- **ボード別ドリルダウン（`drilldown-table`）**: ボードを1つ選択すると、そのボードが使用する物理カラム→表示名の対応を一覧表示

### 呼び出すAPI

| メソッド | パス | 用途 |
|---------|------|------|
| GET | `/`, `/index.html` | 画面本体（`INDEX_HTML`）を返す |
| GET | `/api/columns` | メイン一覧データ（`fetch_data`）を返す。`lineage.db`未存在時は404 |
| GET | `/api/patterns` | 多対1候補・類似度候補（`fetch_cross_column_patterns`）を返す。`lineage.db`未存在時は404 |
| GET | `/api/board_details` | ボード別ドリルダウン用データ（`fetch_board_details`）を返す。`lineage.db`未存在時は404 |
| GET | `/api/whitelist` | ホワイトリスト登録内容（`load_whitelist_entries`）を返す |
| POST | `/api/whitelist` | ホワイトリストへ1件追加（`_handle_whitelist_add`。`table_name`/`column_name`必須、`reason`任意） |
| POST | `/api/whitelist/delete` | ホワイトリストから1件削除（`_handle_whitelist_delete`） |
| POST | `/api/connect` | Dr.Sum接続情報を受け取り`main.py`を実行して`lineage.db`を更新（`_handle_connect`。`--connect`起動時のみ有効、`host`/`db`/`user`/`jdbc_jar`/`backup_dir`必須） |

静的配布版・アップロードモードでは上記APIを呼ばず、`EMBEDDED_DATA`としてページ内に埋め込まれたデータ、またはブラウザ内sql.jsでの解析結果を直接描画する。

- ブラウザ内評価モード（sql.js）: `INDEX_HTML`内の`UPLOADED_MODE`分岐（DD-006）

### 読み取り / 書き込みテーブル

| テーブル | 操作 | 用途 |
|---------|------|------|
| `columns`（`lineage.db`） | SELECT | Dr.Sum側の物理カラム一覧（`table_name`/`table_type`/`column_name`/`data_type`） |
| `aliases`（`lineage.db`） | SELECT | MotionBoard側の表示名（`display_name`/`board_name`/`item_id`/`usage_type`=`alias`or`calc`/`source_file`） |
| `naming_whitelist.json`（DBではなくJSONファイル、既定パスはルート直下） | 読み取り／追記／削除 | 除外対象カラム（`table_name`/`column_name`/`reason`）の管理。`web_viewer.py`起動時に未存在でもエラーにならず、画面からの追加操作で新規作成される（DD-003） |

### 主要ビジネスロジック位置

| ルール | 位置 | 概要 |
|--------|------|------|
| `lineage.db`未存在時のガード | `web_viewer.py:1243`（`_require_db`） | `sqlite3.connect()`が存在しないファイルを自動生成してしまう不具合を防止（DD-007で発覚） |
| ホワイトリスト対象の判定（1対多・多対1・類似度候補のみ対象） | `web_viewer.py:600`（`whitelistAddButton`）、`match_aliases.py` | 「物理名そのまま」「未使用カラム」は事実の指摘のため除外対象外 |
| 統計カードの定義・クリック絞り込み | `web_viewer.py:560`（`CARD_DEFS`）、`web_viewer.py:625`（`renderCards`） | クリック可能なカードは`key`を持つもののみ（表記ゆれ候補・物理名そのまま・未使用カラム） |
| 列の表示順入れ替え・値ソート | `web_viewer.py`内`MAIN_COLUMN_DEFS`/`columnOrder`/`renderTableHeader`（DD-009 Phase 3・4） | 列見出しの←/→ボタンで`columnOrder`を入れ替え、クリックで3段階（昇順→降順→初期順）ソート |
| 静的／アップロードモードでの書き込み系UI非表示 | `web_viewer.py:600`ほか`STATIC_EXPORT`/`UPLOADED_MODE`判定 | 保存先サーバーが無いモードではホワイトリスト追加・削除ボタンを描画しない |

## 過去トラブル・既知の落とし穴

- **発生時期**: DD-007実装時 / **症状**: `--connect`起動直後、`lineage.db`がまだ無い状態で`/api/columns`等を呼ぶと、`sqlite3.connect()`が空のDBファイルを自動生成してしまい、以後の判定がおかしくなる / **原因**: SQLiteの`connect()`は対象ファイルが無ければ新規作成する仕様 / **恒久対策**: `_require_db`でファイル存在確認を行い、無ければ404＋案内メッセージを返すガードを追加 / **関連DD**: DD-007
- **発生時期**: DD-009 Phase 3実装後の社内レビュー / **症状**: 列ソートした状態のままモード切替（デモ⇄実データ）やDr.Sum再接続でデータを再読み込みすると、矢印表示は残るのに新データは未ソートのまま、という表示と実体の不整合が発生 / **原因**: `handleLoadUploaded`・`mode-demo-btn`・`do-connect-btn`の3箇所がいずれも共通の`load()`本体の外側で呼ばれており、ソート状態のリセット漏れがあった / **恒久対策**: 上記3箇所で`sortColumn = null; updateSortIndicators();`を呼ぶよう修正 / **関連DD**: DD-009
