# 画面仕様書: カラムエイリアス使用状況ビューア

---

## 概要・業務目的

カラムエイリアス使用状況ビューアは、Dr.Sumの物理カラムとMotionBoard上の表示名（エイリアス）の対応関係を一覧確認するために、本ツールの利用者（データ基盤担当者・MotionBoard運用者）が使用する画面。具体的には、`lineage.db`（Dr.Sum側カラム一覧とMotionBoard側エイリアスを突き合わせた結果）を読み込み、表記ゆれ候補・多対1候補・物理名直接使用・未使用カラムなどを一覧表示し、意図的な別名はホワイトリスト登録して除外できる。

本画面は単一のHTML（`INDEX_HTML`）で、以下の3つの提供形態を兼ねる:

| 提供形態 | 起動方法 | 用途 |
|---------|---------|------|
| ローカルサーバー版 | `python web_viewer.py` | 自分のPCで`lineage.db`を確認 |
| 静的配布版 | `python export_static.py`で書き出した単一HTML | Pythonなしで他者に配布・閲覧してもらう |
| ブラウザ内評価モード | ローカルサーバー版の「実データをアップロードして見る」ボタン | サーバーを立てず`lineage.db`をブラウザ内（sql.js）だけで解析して見る |

業務上の位置づけ: `dr_sum_metadata.py`→`board_parser.py`→`match_aliases.py`で生成された`lineage.db`を人が目視確認する、パイプラインの最終段階（利用ガイド参照: [`doc/guide/user-guide.md`](../guide/user-guide.md)）。

## ビジネスルール

| 状態 | 操作 | 結果 |
|------|------|------|
| `lineage.db`が存在する（ローカルサーバー版） | 画面を開く | 一覧・統計カード・ボード別ドリルダウンが表示される |
| `lineage.db`が未生成（`--connect`起動直後） | 画面を開く | 各APIが404エラーを返し、「Dr.Sumに接続」から作成するよう案内される（`_require_db`、DD-007） |
| カラムの表示名が複数種類ある（1対多） | - | 「表記ゆれ候補」として一覧行がオレンジ表示＋赤枠バッジになる |
| 異なる物理カラムに同じ表示名がある | - | 「多対1マッピング候補」テーブルに別行で表示される（本体一覧とは別枠） |
| 表示名が1件もなく物理名がそのまま使われている | - | 「物理名そのまま」バッジが付く。ホワイトリスト対象外（事実の指摘のため） |
| ボードのエイリアスが接続中DBの物理カラムと一致しない（`match_aliases.py`が`table_type='(不明)'`で仮登録） | - | テーブル名の横に「DB不一致の可能性」バッジが付く。関係ない別DBのボード定義混入や、Dr.Sum側のカラム名変更/削除が原因の可能性がある（DD-025） |
| MotionBoardのどのボードからも参照されていない | - | 「未使用（孤立項目）」として表示。ホワイトリスト対象外 |
| 表記ゆれ候補・多対1候補・類似度候補の行 | 「ホワイトリストに追加」→ 理由（任意）を入力して登録 | 当該カラムが以後の表記ゆれ集計から除外される（`naming_whitelist.json`に追記）。登録後も検索語・カード絞り込み・列ソート・列並び替え・ドリルダウン選択中のボードは維持される（DD-014） |
| ホワイトリスト登録一覧の行（通常モードのみ） | 「削除」をクリック | 即削除はされず、対象カラム名を明示した確認（「削除する」/「キャンセル」）がその場に展開される。「削除する」を押すまで`/api/whitelist/delete`は呼ばれない（DD-014） |
| 静的配布版／アップロードモードで閲覧 | ホワイトリスト追加・削除を試みる | ボタン自体が表示されない（保存先サーバーがないため。`STATIC_EXPORT`/`UPLOADED_MODE`判定） |
| `--connect`未指定でローカルサーバー起動 | 「Dr.Sumに接続」フォームから取得を実行 | 403エラー（`connect_enabled`が`False`のため無効） |
| カラム数が3000件（`LARGE_DATASET_WARNING_THRESHOLD`）を超える | 画面を開く | ヘッダー付近に「表示が重くなる可能性があります」という警告バナーが表示される。ローカルサーバー版・静的配布版の両方で表示される（DD-014。以前はターミナル標準出力のみだった） |
| 物理カラムが複数ボードで使われている | - | 「使用ボード」列に、ボードごとに「ボード名｜表示名」を1行目とし、同ボードの追加の表示名／計算式名はその下に重ねて表示される。どのボードがどの表示名を使っているかが一覧のまま分かる（DD-016。DD-020で表示形式を変更）。セル全体をグリッド表示にしており、複数ボードが並ぶ場合もボード名列の幅が揃い、区切り線・表示名の開始位置が一致する（DD-021） |
| 使用ボードが4件以上ある | - | 先頭3件のみ表示され、「他N件 すべて表示」ボタンが出る。クリックすると残りのボードが展開され、ボタンは「折りたたむ」に変わる。再クリックで元の省略表示に戻る（DD-021。`title`ホバーでの全件表示は従来どおり併用可） |
| メイン一覧の物理カラム名（`<code>`リンク） | クリック | 画面右の空きスペース（幅が無い場合は一覧の下）にそのテーブルの全カラム定義（物理カラム名・データ型）がサイドパネル表示され、クリックしたカラムの行が黄色で強調される（DD-020） |
| テーブル定義パネルのデータ型が数値（Dr.Sum実機で`column_type`が内部数値コードのまま返る場合） | - | 実機確認済みの3コード（`0`=VARCHAR、`3`=DATE、`7`=NUMERIC）はそのまま型名で表示される。それ以外の数値は、横に「(内部コード)」という注記が付き、ホバーすると「Dr.Sum内部の数値コードです。型名への変換は未対応のため...」という説明が表示される。型名（`VARCHAR`等）が元から取得できている場合はそのまま表示される（DD-021で注記表示を追加、DD-024で確認済み3コードの型名変換を追加。D-004参照） |

## 権限・認可

### ロール × 操作 マトリクス

本画面は認証機構を持たない単一ロール運用のため、ロール区分はない。提供形態によって操作可否が変わる。

| 操作 | ローカルサーバー版（通常起動） | ローカルサーバー版（`--connect`起動） | 静的配布版／アップロードモード |
|------|:---:|:---:|:---:|
| 画面表示・検索・絞り込み・ドリルダウン | ✅ | ✅ | ✅ |
| ホワイトリストへの追加・削除 | ✅ | ✅ | ❌（表示のみ、ボタン非表示） |
| Dr.Sumへの接続・`lineage.db`再生成 | ❌（フォーム自体はあるが403） | ✅ | ❌ |

### 認可境界（どの層で守っているか）

| 層 | 制御内容 |
|----|--------|
| ネットワーク到達性 | `web_viewer.py`は`ThreadingHTTPServer`をlocalhostのみで待受（外部公開しない設計。AGENTS.md） |
| API（`/api/connect`） | `Handler._handle_connect`が`self.server.connect_enabled`（`--connect`フラグ由来）を確認し、無効時は403を返す |
| フロントエンド表示 | `STATIC_EXPORT`/`UPLOADED_MODE`フラグでホワイトリスト操作ボタン・接続フォームの表示有無を切り替える（表示制御のみで、バックエンド側ガードの代わりにはしていない） |
| 認証情報の扱い | Dr.Sumパスワードはクエリ文字列・コマンドライン引数に乗せず、`/api/connect`のPOSTボディ経由で受け取り、`main.py`実行時は環境変数`DR_SUM_PASSWORD`に渡す（`_handle_connect`） |

## 画面UI仕様

### 主要UI要素

- **更新用コマンド入力補助（`update-hint`）**: フォーム（バックアップフォルダ・ホスト名・DB名・ユーザー名・JDBCドライバーパス）に入力すると、`lineage.db`再生成用のコマンドが生成され、コピーボタンで取得できる（DD-008/DD-009）。入力値は常にダブルクオートで囲んでからコマンド文字列に組み込むため、MotionBoardの既定フォルダ名（`[My Boards]`等）のようにスペースを含むパスでもそのままコピペして実行できる。コマンド表示のフォントサイズも拡大済み（DD-016）。「コピー」の隣の「ターミナルを開く」ボタンを押すと、`/api/open_terminal`経由でサーバー側（Windows専用）がコマンドをクリップボードに乗せたうえでcmd.exeを新規ウィンドウとして起動し、SendKeysでその場にペーストする。Enterキーは送らないため未実行のまま残り、確認してから実行するかはユーザー次第（DD-029）。ペーストはタイミング依存で失敗することがあるが、その場合もクリップボードにコマンドが残るため手動貼り付け（Ctrl+V）で代替できる。クリップボードに渡す一時ファイルはBOM付きUTF-8（`utf-8-sig`）で書き出し、PowerShell側の`Get-Content`にも`-Encoding utf8`を明示している（Windows PowerShell 5.1はBOM無しUTF-8をシステムのANSIコードページとして誤読し、日本語が文字化けするため。DD-031）。入力欄に未入力の項目がある状態では、生成コマンドが`<プレースホルダ名>`のまま（`cmd.exe`にリダイレクト記号と誤認される`<`/`>`を含む）になるため、クリック時に未入力項目を検知してターミナルを開かず警告するガードを入れている（DD-031）
- **モード切替（`mode-toggle`）**: 「実データをアップロードして見る」「Dr.Sumに接続」の2ボタンで、それぞれのパネルを開閉トグルする（クリックで開く／再クリックで閉じる）。既定表示そのものを指すだけだった「このデータを見る」ボタンは廃止した（DD-016）
- **アップロードパネル（`upload-panel`）**: `lineage.db`ファイルと`naming_whitelist.json`（任意）をブラウザ内（sql.js）で読み込み、サーバーなしで同じ画面を描画する（DD-006）。どちらの入力欄かが分かるよう「①lineage.dbファイル(必須)」「②ホワイトリストファイル(naming_whitelist.json・任意)」のラベルを付与（DD-016）
- **接続パネル（`connect-panel`）**: ホスト名・DB名・ユーザー名・パスワード・JDBCドライバーパス・MotionBoardバックアップフォルダ・ホワイトリストファイル（任意）・類似度閾値（任意）を入力し「取得」を実行すると`/api/connect`経由で`main.py`を実行する（DD-007）
- **統計カード（`cards`）**: 総カラム数・表記ゆれ候補・使用箇所(延べ)・カスタム項目/計算式で使用・物理名そのまま・未使用カラム・多対1候補・類似度候補の8種。「総カラム数」「使用箇所(延べ)」を除く6枚はクリックで一覧を絞り込める（トグル式）。「多対1候補」「類似度候補」クリック時は、該当する物理カラムの行のみにメイン一覧が絞り込まれる（DD-016で「カスタム項目/計算式で使用」「多対1候補」「類似度候補」も絞り込み対応・ホバー説明追加）
- **検索ボックス（`search`）**: 物理カラム名・テーブル名・表示名・ボード名の部分一致でメイン一覧を絞り込む
- **大規模データ警告バナー（`large-dataset-warning`）**: カラム数が3000件（`LARGE_DATASET_WARNING_THRESHOLD`）を超えると、ヘッダー付近に警告文を表示する。ローカルサーバー版・静的配布版の両方で共通の`renderAll()`から表示される（DD-014）
- **メイン一覧テーブル**: テーブル/ビュー名・物理カラム名・表示名（複数バッジ表示、表記ゆれは警告色）・使用状況（計算式使用・未使用）・使用ボードを表示。「テーブル/ビュー」列は、`table_type='(不明)'`（接続中DBの物理カラムと一致しないエイリアスの仮登録。`match_aliases.py`）の行にのみ「DB不一致の可能性」バッジを表示する。ホバーすると「関係ない別DBのボード定義混入」「Dr.Sum側のカラム名変更/削除」の可能性を説明する（DD-025）。「使用ボード」列はボードごとに「ボード名｜表示名」を1グループとして表示し、同ボードの追加の表示名／計算式名（`計算式: xxx`）はその下に重ねる（`/api/board_details`のデータを再利用。DD-016で実装、DD-018でカンマ区切りの1行表示から箇条書きに変更、DD-020で「ボード名｜表示名＋重ね表示」に変更）。セルをCSS Gridで構成し、複数ボードが並ぶ場合もボード名列の幅を揃えて区切り線・表示名の開始位置を一致させている（DD-021）。件数が多い場合は先頭3件＋「他N件 すべて表示」ボタンとし、クリックで残りのボードの表示/非表示を切り替えられる（全件は`title`ホバーでも確認可能。DD-021でトグルボタンを追加）。「表示名(エイリアス)」列の各バッジもホバーすると、その表示名／計算式名を実際に使っているボード名が表示される（DD-018）。列見出しはドラッグ&ドロップで表示順を入れ替え可能（DD-009 Phase 3で実装した←/→ボタンはDD-020で廃止しドラッグに統一）、列見出しクリックで値の昇順/降順/初期順ソートが可能（DD-009 Phase 4）。物理カラム名をクリックすると、画面右の空きスペース（無ければ一覧下にインライン表示）にそのテーブルの全カラム定義がサイドパネル表示され、クリックしたカラムの行が強調される（DD-020）。データ型が数値のみの場合、実機確認済みの3コード（`0`=VARCHAR、`3`=DATE、`7`=NUMERIC）はそのまま型名で表示し、それ以外は「(内部コード)」という注記を付け、Dr.Sum内部コードであり型名への変換が未対応であることをホバーで説明する（DD-021で注記表示、DD-024で3コードの型名変換を追加）
- **多対1マッピング候補テーブル**: 異なる物理カラムが同一表示名を持つ組を一覧表示
- **類似度候補テーブル**: 表示名同士の類似度（`--similarity-threshold`、既定0.8）に基づく表記ゆれ候補ペアを一覧表示
- **ホワイトリスト一覧テーブル**: 登録済みの除外設定（テーブル名・物理カラム名・理由）を表示。通常モードのみ「削除」ボタンあり。クリックすると即削除ではなく、対象カラム名を明示した確認UI（「削除する」/「キャンセル」）がその場に展開される（DD-014）
- **ボード別ドリルダウン（`drilldown-table`）**: ボードを1つ選択すると、そのボードが使用する物理カラム→表示名の対応を一覧表示。選択中のボードはホワイトリスト登録・削除後のデータ再読込後も保持される（DD-014）。「種別」列は「エイリアス」（表示名がMotionBoard上で設定されている）・「物理名そのまま」（表示名が設定されず物理カラム名がそのまま使われている。メイン一覧「使用ボード」欄のDD-022と同じ判定）・「計算式」（カスタム項目・事後計算項目の計算式内で参照されている）の3種に区別して表示する。「種別」「アイテムID」の列見出しはホバーで各項目の意味を説明する。「アイテムID」はボード定義ファイル内でその項目を識別する内部ID（デバッグ用の補助情報であり、画面上のパーツ番号ではない）（DD-032）
- **他DBのボードのため除外（`excluded-aliases-table`）**: 画面最下部に表示。`<DataSource type="drsum">`の`src`属性（`{DB名}/{テーブル名}`形式）から読み取った所属DB名が、接続中のDBと異なることが確定しているエイリアスは、メイン一覧（DD-025の「DB不一致の可能性」バッジ対象）には含めず、ここに所属DB名・テーブル/ビュー名・物理カラム名・表示名・ボード名の一覧として分けて表示する。見出しに件数を表示する（DD-026）。専用の検索欄（`excluded-aliases-search`）があり、表示名（エイリアス名）だけ分かっていて所属DBが不明な場合でも、物理カラム名・テーブル名・ボード名・所属DBを含めた部分一致で絞り込める。メイン一覧の検索ボックス（`search`）とは独立しており、互いの検索語は影響しない。見出しの件数は常に全件数を表示し、検索で0件になった場合は「検索条件に一致するエイリアスはありません」と表示を区別する（DD-029）

### 呼び出すAPI

| メソッド | パス | 用途 |
|---------|------|------|
| GET | `/`, `/index.html` | 画面本体（`INDEX_HTML`）を返す |
| GET | `/api/columns` | メイン一覧データ（`fetch_data`）を返す。`lineage.db`未存在時は404 |
| GET | `/api/patterns` | 多対1候補・類似度候補（`fetch_cross_column_patterns`）を返す。`lineage.db`未存在時は404 |
| GET | `/api/board_details` | ボード別ドリルダウン用データ（`fetch_board_details`）を返す。`lineage.db`未存在時は404 |
| GET | `/api/excluded_aliases` | 「他DBのボードのため除外」セクション用データ（`fetch_excluded_aliases`）を返す。`lineage.db`未存在時は404、`excluded_aliases`テーブル自体が無い（DD-026より前のlineage.db）場合は空配列（DD-026） |
| GET | `/api/whitelist` | ホワイトリスト登録内容（`load_whitelist_entries`）を返す |
| POST | `/api/whitelist` | ホワイトリストへ1件追加（`_handle_whitelist_add`。`table_name`/`column_name`必須、`reason`任意） |
| POST | `/api/whitelist/delete` | ホワイトリストから1件削除（`_handle_whitelist_delete`） |
| POST | `/api/connect` | Dr.Sum接続情報を受け取り`main.py`を実行して`lineage.db`を更新（`_handle_connect`。`--connect`起動時のみ有効、`host`/`db`/`user`/`jdbc_jar`/`backup_dir`必須） |
| POST | `/api/open_terminal` | `command`文字列を受け取り、クリップボードに乗せたうえでcmd.exeを新規起動しSendKeysでペーストする（`_handle_open_terminal`。Windows専用、`os.name != "nt"`時は400。`--connect`の有効/無効を問わず常時有効。資格情報は扱わない） |

静的配布版・アップロードモードでは上記APIを呼ばず、`EMBEDDED_DATA`としてページ内に埋め込まれたデータ、またはブラウザ内sql.jsでの解析結果を直接描画する。

## 実装仕様（LLM・開発者向け）

- フロントエンド本体（HTML/CSS/JS、`INDEX_HTML`）: `web_viewer.py:45`〜
- バックエンドハンドラ（`do_GET`/`do_POST`、`Handler`クラス）: `web_viewer.py:1703`〜。`/api/open_terminal`の実処理は`_handle_open_terminal`（DD-029）
- データ取得ロジック: `fetch_data`（`web_viewer.py:1590`。DD-020でテーブル定義パネル用に`data_type`を追加）、`fetch_cross_column_patterns`（`web_viewer.py:1640`）、`fetch_board_details`（`web_viewer.py:1648`）、`fetch_excluded_aliases`（`web_viewer.py:1675`。DD-026。`excluded_aliases`テーブル不在時は空配列を返す）

## 過去トラブル・既知の落とし穴

- **発生時期**: DD-007実装時 / **症状**: `--connect`起動直後、`lineage.db`がまだ無い状態で`/api/columns`等を呼ぶと、`sqlite3.connect()`が空のDBファイルを自動生成してしまい、以後の判定がおかしくなる / **原因**: SQLiteの`connect()`は対象ファイルが無ければ新規作成する仕様 / **恒久対策**: `_require_db`でファイル存在確認を行い、無ければ404＋案内メッセージを返すガードを追加 / **関連DD**: DD-007
- **発生時期**: DD-009 Phase 3実装後の社内レビュー / **症状**: 列ソートした状態のままモード切替（デモ⇄実データ）やDr.Sum再接続でデータを再読み込みすると、矢印表示は残るのに新データは未ソートのまま、という表示と実体の不整合が発生 / **原因**: `handleLoadUploaded`・`mode-demo-btn`・`do-connect-btn`の3箇所がいずれも共通の`load()`本体の外側で呼ばれており、ソート状態のリセット漏れがあった / **恒久対策**: 上記3箇所で`sortColumn = null; updateSortIndicators();`を呼ぶよう修正 / **関連DD**: DD-009
- **発生時期**: DD-014実装時 / **症状**: `initBoardDrilldown`が呼ばれるたびに`<select id="board-select">`へ`change`リスナーを追加しており、DD-014で登録・削除を`location.reload()`無しのその場更新に変更すると、操作のたびにリスナーが重複登録されて`renderDrilldown`が多重発火する状態になるところだった / **原因**: リスナー登録がデータ再読込の都度呼ばれる関数の内側にあった（従来は`location.reload()`でページごと作り直されるため表面化していなかった） / **恒久対策**: `change`リスナーの登録をページ初期化時の1回だけに切り出し、`initBoardDrilldown`はoption再構築と選択状態の復元のみを行うよう分離 / **関連DD**: DD-014
- **発生時期**: DD-016起票のきっかけ（ユーザー実機報告） / **症状**: 「🔧 データを更新するには」で生成したコマンドをそのままターミナルにコピペすると、MotionBoardバックアップフォルダ（既定で`[My Boards]`のようにスペースを含む）のパスが途中で2引数に分割され、`main.py`が`unrecognized arguments`で終了する / **原因**: `updateCommandPreview`が入力値をクオートせずコマンド文字列に連結していた（`/api/connect`側の`subprocess.run`はリスト渡しのため元々安全で、画面のコマンド生成テキストのみの問題だった） / **恒久対策**: 各値を`"..."`で囲んでから連結するよう修正 / **関連DD**: DD-016
- **発生時期**: DD-029実装直後の実機確認 / **症状**: 「ターミナルを開く」で貼り付けたコマンドの日本語部分がクリップボード上で文字化けし、さらに入力欄が未入力のまま実行すると`<プレースホルダ名>`の`<`/`>`が`cmd.exe`にリダイレクト記号と解釈され「コマンドの構文が誤っています」になった / **原因**: `_handle_open_terminal`がBOM無しUTF-8で一時ファイルを書き出し、Windows PowerShell 5.1の`Get-Content`（エンコーディング未指定）がシステムのANSIコードページとして誤読していた / **恒久対策**: 一時ファイルを`utf-8-sig`（BOM付き）に変更し`Get-Content -Encoding utf8`を明示。加えて未入力項目のチェックをクリック時に追加 / **関連DD**: DD-031
- **発生時期**: DD-018実装時 / **症状**: `INDEX_HTML`に埋め込んだJSで`'\n'`と書いたところ、ブラウザで`Uncaught SyntaxError`になりページが描画されなくなった / **原因**: `INDEX_HTML`は生文字列ではない通常のPython三重引用符文字列のため、Pythonパーサが`\n`を実際の改行文字として解釈し、JSの単一引用符文字列内に生の改行が混入して構文が壊れた / **恒久対策**: `'\\n'`（二重バックスラッシュ）と書くことでJS側に正しく`\n`エスケープを渡す。`doc/engineering-patterns.md`パターン#8に昇格済み / **関連DD**: DD-018
